GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。自分のマシン上でリアルタイムに作業するため、VS Code の Copilot Chat では、すべてのツール呼び出しやファイル編集を逐次確認できます。差分をその場でレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトで作業を調整、拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントを誘導し、高コントラストモードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントが、高コントラストモードを実装しています。作業の途中で、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加したいとのことです。新しい会話を最初から始めるのではなく、進行中のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調べたファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの操作を確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選んで変更を採用します。
   - **Undo** を選んで変更を元に戻し、エージェントにもう一度作業させます。
4. チャット上部にある **Files changed** インジケーターを開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出しでターミナルコマンドの実行などの許可を求められると、エージェントは一時停止して **Allow** を表示します。許可する前にコマンドを確認してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。変更内容の要約が表示されます。

## エージェントを誘導してライトモードを追加する

高コントラストモードができたので、同じ会話を続けてライトモードの切り替えを追加します。会話を継続すると、変更したコンポーネント、スタイルの方法、設定を local storage に保存する実装など、前の作業のコンテキストが引き継がれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライトモードの追加案を提示します。
3. 高コントラストモードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を使います。
4. エージェントの進め方が希望と異なる場合、たとえば好みでない方法で切り替え UI をリファクタリングしようとする場合は、チャット入力欄の横にある **Stop** ボタンで停止してから、具体的な追加プロンプトを送ります。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより早く作業できます。追加のプロンプトで変更を依頼できます (例: 「CSS を簡素化し、selector を重複させず CSS variable を使ってください」)、方向を修正できます (例: 「切り替えを3つに増やさず、既存の設定パネルにライトモードを統合してください」)、作業範囲を広げられます (例: 「両方の切り替えにキーボードショートカットも追加してください」)。

## 作業セットをレビューする

commit する前に、エージェントが変更したファイルをまとめて確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage して commit します。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して誘導しました。ファイル編集ごとに確認し、変更を採用または取り消し、コンテキストを保ちながら追加のプロンプトで作業を拡張しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 進行中のセッションで追加プロンプトを使って作業を誘導しました。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更を確認します。
